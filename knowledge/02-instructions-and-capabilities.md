# 指令与实际能力

关联课程：L01。依据是用户提交的指令和输出，以及 2026-11-09 查看到的 [应用代码](../apps/FirstAgent/Program.cs)。用户已口述说明获取状态需要可调用的查询工具；下面其他归纳仍需结合实践验收。

## 四种职责

| 内容 | 本项目中的例子 | 职责 |
| --- | --- | --- |
| Instructions | 用中文、解释研发问题、说明能力边界、800 字以内 | 提供持续的行为要求和角色描述 |
| 用户 prompt | 用两句话说明能提供的帮助和信息限制 | 给出当前任务，与 Instructions 一起参与模型调用 |
| 工具与数据接入 | 后续的服务状态查询或网页搜索 | 提供获取外部信息、执行动作的实际路径 |
| 运行时代码 | 参数校验、权限检查、调用上限、取消、输出验证 | 实施可检查和强制执行的规则 |

## 从本次输出可以得出什么

输出使用中文，覆盖能力与限制，长度在本次要求以内。这说明这一条输出符合要求。它不证明所有输入都符合要求，也不证明模型自述的代码审查能力已经通过质量评测。

Instructions 中的字数要求是行为引导。严格的长度限制需要先约定计数规则，再由代码校验并处理超限结果。token 上限与中文字数不是同一个指标。流式输出如果已经直接显示给用户，结束后才检查无法撤回此前显示的内容，需要另外设计缓冲或显示限制。

## 工具能力不能由一句描述创建

当前代码没有注册网页搜索、浏览或代码执行工具。改变“不能联网”的描述并不会自动创建这些工具。接入功能还需要真实实现、注册、凭据或权限配置以及执行结果处理，最后通过观察调用和结果验证。

模型服务调用本身需要 HTTP 通信，所以对用户描述能力时，宜具体说“当前未接入网页搜索或浏览工具，不能主动检索最新资料”。这比笼统宣称整个应用没有网络更准确。这里判断的是应用显式配置的能力，不推断网关内部实现。

## 比较提示词时固定其他条件

固定模型、用户问题、采样参数和应用配置，只修改一个目标指令。保存多次输出及失败案例。若同时更换模型，无法单独判断差异来自指令还是模型。
