# 两阶段学习路线

最终成果包括：一个有业务价值和评测证据的 MAF 应用、一个有明确边界的自研 Agent 框架、两种业务场景的复用示例，以及能够深入追问的技术讲解材料。

主线项目为“研发知识与故障排查助手”。第一阶段在使用框架时穿插局部源码阅读，第二阶段再系统梳理设计并实现自己的运行时。这样每次阅读源码都有实际问题作为入口。

## 学习前提和节奏

第 0 课确认 C#、异步、依赖注入、HTTP、JSON、单元测试的基础。如果某项薄弱，就在相关课程前补一个小练习。LLM 基础随任务展开，包括 token、上下文窗口、消息角色、采样、结构化输出、工具调用和 embedding。

下列时间是具备基本 .NET 开发能力时的初步规划，包含编码、实验和复盘，不是完成保证。第一阶段约 64–96 小时，第二阶段约 96–138 小时。每周投入时间和目标岗位确认后再安排周计划；通过验收后再进入下一模块。

| L03 会话与输出 | 多轮诊断、会话持久化、结构化诊断结果 | 历史与业务状态、上下文预算、输出验证 | 重启后恢复；两个会话隔离；无效结构被处理 | 8–12 小时 |

L02 就开始积累评测用例，L07 集中形成报告。L05 才引入多 Agent 对照实验：比较“单 Agent + 工具”“显式工作流”“多个角色 Agent”的质量、成本和复杂度，不预设多个 Agent 更好。

每课固定产出四项：可执行结果、一次失败分析、一张知识卡片、一个两分钟口述答案。模块较大时拆成多个 60–120 分钟的小课。

## 第一阶段完成标准

- 应用能够完成有引用的知识回答、工具辅助诊断、审批后的模拟工单创建。
- 单元测试证明确定性逻辑；集成测试证明存储和恢复；真实模型评测证明特定任务下的行为。
- 使用独立保留集评估，报告成功率、失败类别、调用数、延迟和成本；指标定义见 [项目设计](project-brief.md)。
- 能用自己的话追踪“用户请求 → 上下文 → 模型 → 工具 → 状态 → 最终结果”，并指出实际源码位置。
- 能解释至少三个设计取舍，例如检索方法、会话存储、工作流与自主规划的边界。

### 自研范围

第一版实现：模型调用边界、工具注册与执行循环、上下文预算、会话、流式事件、取消与超时、基础中间件、显式工作流、持久化恢复、审批和可观测性。

模型适配器可以复用厂商 SDK，也可使用 `IChatClient` 作为低层接口；学习运行时本身时不使用 `AIAgent` 或自动执行工具的客户端替代自己的循环。`FunctionInvokingChatClient` 用于阅读和对照，核心循环由自己实现。

第二个应用使用独立的工单分类、路由和人工复核数据，检验框架抽象是否脱离了故障排查业务。自研框架不声称兼容 MAF 全部 API，也不以拥有所有集成为结课条件。

以下内容按目标岗位选修：A2A、声明式定义、harness 和上下文压缩策略、分布式任务调度、多租户配额、沙箱执行、模型路由、推理服务和微调。训练大模型不是本路线前置条件；平台岗位需要另外加深分布式系统和模型服务。
