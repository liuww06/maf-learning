# 第 1 课 第一个可观察的 MAF 应用

目标：创建独立 C# 控制台应用，理解 provider、Agent、输入和响应之间的关系，跑通普通响应和流式响应，并观察一次失败。当前已确认使用 Magpie 的 OpenAI Responses 接口。

## 本课当前入口

示范项目已建立并完成助手验证：[FirstAgent 运行说明](../apps/FirstAgent/README.md)。Base URL 为 `http://127.0.0.1:3425/v1`。首次验证使用 `codex/gpt-6.1-sol`，2026-11-09 核对到的源码默认模型已改为 `zcode/GLM-5.3-Flash`；环境变量可以覆盖默认值。

先在学习目录运行：

```bash
dotnet apps/FirstAgent/bin/Debug/net10.0/FirstAgent.dll stream
```

再阅读 [Program.cs](../apps/FirstAgent/Program.cs) 的三个编号部分：SDK 客户端、MAF Agent 创建、响应消费。个人任务是修改 `Instructions`，重新编译后解释输出变化。详细结果见 [首次接入记录](../progress/2026-11-06-l01.md)。

## 配置核对清单

- 已确认 Magpie、Responses 协议，运行时模型以控制台实际显示为准。
- 首次接入已验证 `codex/gpt-6.1-sol` 的普通文本、流式文本和用量报告；其他模型与工具调用、结构化输出分别验证。
- 单次练习和评测批次的费用或调用次数上限仍待确定。
- 认证信息由本地环境变量或合适的凭据机制提供，不写入仓库或学习记录。

只需交流服务名称和预算，不需要在对话中提供密钥。本地模型同样需要验证所选模型的工具调用能力和实际资源占用。

## 本课按这六步完成

| 步骤 | 你要做的事 | 助手提供的支持 | 观察结果 |
| --- | --- | --- | --- |
| 1 | 在 `apps/` 下建立独立控制台项目 | 根据实际 provider 核对安装包和版本 | 明确目标框架和依赖版本 |
| 2 | 配置模型客户端，构造一个 MAF Agent | 讲解每个对象的职责，给最小示例 | 能指出网络请求在哪层发生 |
| 3 | 运行“说明你可以帮助研发人员做什么” | 检查请求配置和错误 | 保存一次脱敏的真实响应 |
| 4 | 使用流式接口运行相同任务 | 解释事件、增量和取消 | 记录首事件与完成时间 |
| 5 | 设置取消或制造可控配置错误 | 协助分辨本地配置、认证、网络和服务错误 | 明确失败发生的层次 |
| 6 | 自己修改 instructions 并解释变化 | 审查实现并提出反例 | 一张知识卡片和两分钟讲解 |

创建项目时锁定实际验证的包版本，保存依赖锁文件；不要把不同版本教程的 API 混在一起。先编译再运行，分别记录结果。需要网络还原依赖时按环境权限要求处理。

## 本课保留的证据

- `dotnet --info` 摘要、项目目标框架、包版本和模型标识。
- 还原与编译命令及退出状态。
- 普通响应、流式事件和可控失败的脱敏记录。
- 可获得的用量；缺失字段明确记为不可用。
- 自己对 provider、Agent、session、tool 四者的初步解释。

本课不凭回答内容好听与否判定成功。重点是你能运行、观察、修改并解释调用；业务工具在 L02 加入。

## 官方资料与版本注意事项

[官方入门教程](https://learn.microsoft.com/en-us/agent-framework/get-started/your-first-agent?pivots=programming-language-csharp) 展示了创建 Agent 和普通、流式调用的基本方式。

2026-11-06 检索到的入门页面 C# 片段与本地源码示例在环境变量命名上存在差异。本地 Foundry 示例使用 `FOUNDRY_PROJECT_ENDPOINT` 和 `FOUNDRY_MODEL`；配置时应核对客户端实际要求的 endpoint 类型，不能仅凭变量名把 Azure OpenAI endpoint 和 Foundry project endpoint 互换。
