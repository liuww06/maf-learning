# 个人思考与知识内化

这里保存学习中真正卡住我的问题、对方案的质疑、认识变化和自己的判断。目标是逐步形成能解释、能实践、能迁移的个人知识储备。

本模块按个人问题组织。[课程](../docs/roadmap.md) 安排实践路径，[知识卡片](../knowledge/00-map.md) 保存可迁移的机制，[学习记录](../progress/tracker.md) 保存过程与证据；个人笔记把这些材料连接到“我为什么这样理解、遇到新情况会怎样选择”。

## 如何积累

- 根据真实讨论自动整理原理问题、概念混淆、设计取舍和有价值的质疑。普通操作与重复问题不单独收录。
- 使用 [个人思考模板](_template.md)。同主题补充新反例、条件和认识变化，保留重要修订，不按每轮聊天新建文章。
- 忠实保留本人原问题与已表达的观点。助手归纳的认识、第一人称表达和面试稿先标为“待本人确认”；没有复述或实践证据时，不写成已经掌握。
- 机制和源码细节优先链接已有知识卡片；本模块重点记录个人理解过程和判断条件。引用实验时说明执行者、版本、结果与适用范围。
- 后续遇到相关练习，引用笔记中的问题进行复述或迁移验证，把实际回答和结果补回原笔记。

## 内化状态怎样推进

| 状态 | 需要留下的证据 |
| --- | --- |
| 整理稿 | 已形成可读笔记，助手归纳部分待本人确认；不表示已经掌握 |
| 能独立复述 | 本人在不看答案时解释机制和至少一个反例，记录回答与日期 |
| 有实现或实验支撑 | 在理解基础上，能说明自己实现或复现了什么、结果证明什么及其边界 |
| 能迁移并解释取舍 | 面对不同需求，能选择或舍弃方案，解释成本、限制和验证方法 |

状态依据当前主题的证据推进。过去已有某段代码或测试通过，可以作为关联证据，但不会自动证明新的设计问题已经理解。发现理解有缺口时，保留原证据，注明待补部分。

## 一次简短复习

1. 先读笔记顶部的三句话速记，再合上正文，用自己的话解释原问题。
2. 保持参考答案折叠，回答自测题，并说明答案在什么条件下会变化。
3. 对照答案，把答不清的地方和修正后的理解补入“本人复述与修订”。
4. 在后续实际练习中验证一个判断，再更新笔记状态及本页索引。

复习记录只保存实际发生的复述和实验。模板、参考答案和阅读次数本身不提升内化状态。
